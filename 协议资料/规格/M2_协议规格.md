## 0. 前置：帧格式（自包含；单一来源 = M1 规格 §1）

| 方向 | 布局 | 长度字段 N | 等级 |
|---|---|---|---|
| S2C（服务器→客户端） | `[N 1B][opcode 1B][data]` | **含** opcode | 〔A〕`FUN_00430fe0` |
| C2S（客户端→服务器） | `[opcode 1B][N 1B][body N]` | **不含** opcode | 〔C〕真机日志 + `tap` 分帧 `desync=0` |
| 两向共同 | `N == 0xFF` → `0xFF + 2B u16 LE` 扩展 | — | 〔A〕/〔C〕 |

★ **两向不对称，不能互推。** 旧版本节把 S2C 的「长度在前」抄成了双向格式并加了一句「双向对称」，
2026-10-22 勘误；错误来源溯源见 M1 规格 §1.3（`entry_protocol_sim.PacketSend()` 的自定包装 +
它自己生成的 `mock_srv_*_after_handshake.bin` 被当成实测抓包）。

**Unpack 语义**（CNetClient 原生）：
- `UnpackInt(n)`：小端 n 字节整数（n=1/2/4）〔B 用法 / C 真机字段可解〕
- `UnpackSigned(n)`：有符号 n 字节〔B〕
- `UnpackString(0)`：变长字符串 = **GBK 字节 + `\0` 结尾（C 字符串，无长度前缀）**〔C〕
  ★2026-10-15 客户端实测修正：旧结论 `[1B len][GBK]` 中长度字节会被渲染为名字前的「口」，
  且无 `\0` 时字符串越界读吞掉后续帧字节（战斗卡「请等待」的直接原因）
- `UnpackString(n>0)`：定长 n 字节字符串〔B〕
- `UnpackDesc`（prop.py）：`[n 1B] + n×子项（t 1B + 参数）`，最小合法值 n=0 → 1 字节〔B〕
- 补丁 DLL（+0x72=0）→ 全链路明文〔A 开关 / C 可跑通〕

## 1. 进世界调用链（客户端视角）

```
选角界面(selectrole) → 点角色 → C2SLoginPlayerEnter(id)   [opcode=2, 帧体=id 4B]
   │
   ▼ 服务器回 S2CPropInit（opcode=16）
   │  nethero.S2CPropInit：hero.g_ID=UnpackInt(4) → hero.CreateProp(netobj)
   │  → 隐藏 loginin/selectrole/createrole → mainmenu.Show(True)   ← 进入游戏主界面
   ▼ 服务器回 S2CMapSceneM（opcode=96）
   │  map.Load(scene, mapid, minimapid, args, scenename) → hero.CreateHero(x,y)
   ▼ 服务器回 S2CMapAddNpc / S2CMapAddPlayer（opcode 99/98）→ 场景对象
   ▼ 服务器回 S2CMapGotoM（opcode=97）→ 角色定点
```

> S2CLoginRoleEnter（opcode=4）脚本层是空实现——服务器**不需要**回它，直接发 PropInit。

## 3. 地图场景帧（netmap）

### S2CMapSceneM（opcode 96）
```
scene(2B)
 ├─ scene==0xFFFF → 动态地图: scene(2B)+mapid(4B)+2B+2B+2B+1B+1B
 ├─ scene==0xFFFE → 副本房间: scene(2B)+7×1B 房间参数+n(2B)+n×2×1B 不可通行对
mapid(2B) minimapid(2B) x(2B) y(2B) scenename(变长)
```
客户端 `map.Load(scene,mapid,minimapid,args,scenename)` → `hero.CreateHero(x,y,desc)` 放置自己。

### S2CMapGotoM（opcode 97）
```
x(2B) y(2B)          → hero.g_Hero.SetServerPos + Stand
```

### S2CMapAddPlayer（opcode 98）
```
id(4B) shape(2B) x(2B) y(2B) desc(UnpackDesc)
country(1B) hideflag(1B)        （hideflag≠0 → shape=9999 隐藏）
emotetype(1B) s(1B) playername([s]字节) emotefortitle(1B)
title(定长22) color(1B) update_flag(1B)
```

### S2CMapAddNpc（opcode 99）
```
id(4B) shape(2B) x(2B) y(2B) block(1B) desc(UnpackDesc)
direct(1B)                       bit7=hide bit6=special 低5位=方向
npctype(2B) country(1B)          高4位=emotetype 低4位=country
addonId(2B) title_len(1B) [title(title_len)若≠0] name(变长)
```

### S2CMapDel（opcode 85）
```
GetCmdLen()==8 → 8×1B（矩形区域删除: sx sy ex ey sx1 sy1 ex1 ey1）
否则 → id(4B)（删除场景对象及其队伍/召唤物）
```

### S2CMapTrack（opcode 86）—— 对象移动同步
```
id(4B) x(2B) y(2B) dx(1B signed) dy(1B signed) move_type(1B)
```

## 4. 完整进世界序列（模拟服实现参考）

```
① 收 C2SLoginPlayerEnter(id)      opcode=2, 帧体=id 4B
② 回 S2CPropInit                  opcode=16: id + 67 项属性（m_Desc=n=0）
③ 回 S2CMapSceneM                 opcode=96: scene(<0xFFFE) mapid minimapid x y 场景名
④ 回 S2CMapAddNpc（若干）         opcode=99: 摆静态 NPC
⑤ 回 S2CMapAddPlayer（可选）      opcode=98: 场景其他玩家
⑥ 回 S2CMapGotoM                 opcode=97: x y
```

## 5. 易错点

1. **scene 值**：S2CMapSceneM 的 scene 为 0xFFFF/0xFFFE 时走特殊分支（动态/副本），普通场景直接给 scene<0xFFFE
2. **UnpackDesc 变长**：m_Desc/desc 字段结构为 `[n][子项…]`，n=0 时仅 1 字节（最小合法）
3. **定长 vs 变长字符串**：AddPlayer 的 playername 是「显式 1B 长度 + 内容」、title 是定长 22；AddNpc 的 name 是变长（`UnpackString(0)`）
4. **TLONG（m_Cash）= 2×UnpackInt(4) = 8 字节**
5. **PropInit 的 m_HP…m_Con_All 等共 26 个 TWORD 连续**，漏一个即字段错位
