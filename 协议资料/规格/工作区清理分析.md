## 二、重大发现：规范工具链存在 STRINGREF 解析 bug（已修复并验证）

`Claw/tools/pymarshal26.py`（ canonical 读取器）的 `TYPE_STRINGREF` 解析有索引漂移 bug：
游戏 marshal 写入端 refs 表**只含字符串**，而读取端在 `TYPE_CODE` 时也向 refs 追加 code 对象，导致字符串引用索引整体错位。

- 修复前实测：**484 个脚本中 394 个受影响**，names/consts 中混入 18,165→**18,265 处错误解析**（CodeObject 冒充字符串；另有不可见的"错串"静默污染）
- 修复（2026-10-14-04-22-42 会话已结论、本轮合并落地）：仅在已 intern 的字符串中按序解析
- 修复后验证（托管 Python 3.13，全量 484 脚本）：

| 指标 | 修复前 | 修复后 |
|---|---|---|
| drift 文件 / 条目 | 394 / 18,265 | **0 / 0** |
| 解析失败 | 0 | 0 |
| code object 数 | 19,468（含 2,451 个幽灵重复计数） | **17,017（真实）** |
| 指令数 | 1,681,051 | 1,536,528 |
| opcode 覆盖率（opmap_coverage.py） | 99.87%（0.13% 未映射） | **100.0000%（0 未映射）** |
| 结构不变量（opmap_validate2.py V1–V6） | — | **0 违例**（484 文件 / 17,017 code object / 1,536,528 指令；V4 MAKE_FUNCTION 16,533 全 ok；V6 无截断） |

> 结论：该 bug 正是 README 所记"未识别率 0.13%"的根源——未映射指令全部来自幽灵 code object。修复后 P0 映射表在真实语料上达到完全覆盖。
> 注：`opmap_e2e_cf.py` 报告 400 处栈"下溢"为其线性栈模拟的既有启发式局限（POP_TOP/RETURN_VALUE 深度模型不含 SETUP_FINALLY 等效应），与本次修复无关——补丁不改变 co_code 字节流。
