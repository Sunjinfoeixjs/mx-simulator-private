## 0. 帧格式与全局约定（自包含；单一来源 = M1 规格 §1）

### 0.1 证据等级（与 M1 §0 同口径）

| 等级 | 含义 |
|---|---|
| 〔A〕 | 二进制 / 指令级实证（`mxmain.dll` 反汇编、`UnpackBit` 核心 `0x41A4D0`、marshal 原始字节） |
| 〔B〕 | 客户端脚本源码（`src/*.py` 反编译：字段顺序、分支、UI 行为） |
| 〔B⁺〕 | **脚本字节码级**：`src/*.pyc` 代码对象反汇编（逐条 `PacketAddI` 压栈顺序与宽度）。比〔B〕强——排除 decompiler 误排/漏语句，尤其能查「形参有、线上无」的字段 |
| 〔C〕 | 真机运行观测（`logs/m4_srv_*.log`、`tap` 分帧 `desync=0`、录像帧、截图） |
| 〔D〕 | 推导（由 A/B/C 外推，**该环节无直接观测**） |
| 〔E〕 | 未还原 / 存疑 |

约定：结论句尾标**最高**证据等级；「源码上如此」只能是〔B〕，不得写成「实测」。

### 0.2 帧格式（★两向不对称，不可互推）

| 方向 | 布局 | 长度字段 N | 等级 |
|---|---|---|---|
| S2C（服务器→客户端） | `[N 1B][opcode 1B][data]` | **含** opcode | 〔A〕`FUN_00430fe0` |
| C2S（客户端→服务器） | `[opcode 1B][N 1B][body N]` | **不含** opcode | 〔C〕真机日志 + `tap` 分帧 `desync=0` |
| 两向共同 | `N == 0xFF` → `0xFF + 2B u16 LE` 扩展 | — | 〔A〕/〔C〕 |

> **2026-10-22 勘误**：M1/M2 旧版曾写「双向同格式（对称协议）」，那是把 S2C 收包函数
> 的结果外推到发送方向（来源是 `entry_protocol_sim.PacketSend()` 的自定包装 + 合成的
> `mock_srv_*_after_handshake.bin`）。正确格式见上表，详见 M1 规格 §1.3。
> 本档自 2026-10-15 起写的就是不对称版，**未受该错误影响**。

其余约定：

```
变长字符串 UnpackString(0) = GBK 字节 + \0 结尾（C 字符串，★无长度前缀）   〔C：截图+吞帧实证〕
UnpackDesc 空值 = 单字节 0x00（n=0）                                      〔B〕
补丁 DLL（+0x72=0）→ 全链路明文                                           〔A 开关 / C 可跑通〕
```

S2C 路由表（`net.py NET_FUNCTION_NAME`）〔B〕：C2S 与 S2C 是**独立编号空间**（同为 96，C2S=点击NPC，S2C=场景SceneM）。

### 0.3 字段定义只有一份：`sim/frames.py`（生成的收发包）

战斗帧的字段此前有**三份**实现（`build_war_*` 手写打包 / 分派里手写 `body[0]`、`struct.unpack` /
`tap.OVERLAY` 解码串），各自漂移过一次（166 条件字段、169 缺 id、115/123 位序）。现在收敛为：

| 组件 | 角色 |
|---|---|
| `frames.SPEC` | **唯一字段定义**：帧名 → (opcode, 方向, 规格串)。规则见该文件头部（`N`/`Ns`/`s`/`fN`/`D`/`T`/`B(子名:最高位:位宽)`/`if(表达式)`） |
| `frames.pack_s2c(name, **kw)` | 由定义**生成**帧体；`m4_server.build_war_*` 只做参数搬运 |
| `frames.unpack_c2s(op, body)` | 由同一定义**生成**收包解析；分派与 `_finish_pet_turn` 不再手写字节偏移 |
| `frames.tap_specs()` | 派生调试台规格，`tap.py` 用 `_OV_S2C.update(...)` 注入（战斗帧不再手写第三份） |

三条不变式（由 `tests/_test_battle_flow.py` 与 `tests/_test_tap.py` 守着）：

1. **吃满**：`unpack_s2c(op, body)['_len'] == len(body)`——多读/少读都会判红，等于给字段宽度上了回归；
2. **同源**：服务端发出去的字节必须能被同一份定义解开（帧序断言写在解出来的字段上，不是 `body[3:5]`）；
3. **可截断**：帧体不足时 `unpack_*` 返回 `None`，由调用方的兜底分支处理（与旧行为一致）。

扩展方式：只改 `frames.SPEC` 一行；`python sim/frames.py` 会跑内建往返自检（位域、条件字段、无 `\0` 变长串）。
注意 `desc` 目前只支持**空值**（战斗帧要求发空 desc，见 §3 易错点 3），非空 desc 需按 `UnpackDesc` 标签表另解。

## 1. 移动

| 方向 | opcode | 帧体 | 等级 |
|---|---|---|---|
| C2S | 54 (C2S_MAP_MOVE) | x(2) y(2) len(trace)(1) [trace 方向 ×len] | 〔B〕字段 /〔C〕真机实发 |
| S2C | 86 (S2CMapTrack) | id(4) x(2) y(2) dx(1**有符号**) dy(1**有符号**) move_type(1) | 〔B〕字段 /〔C〕真机回弹修复 |

**★ 2026-10-16 真机修复（角色回弹）**：`C2SMapMove` 的 (x,y) 是**起点**，
终点 = 起点 + trace 各方向增量（方向表见 `src/nethero.py` `_offset`：1 右上/2 左上/
3 左下/4 右下/5 上/6 左/7 下/8 右）。`S2CMapTrack` 语义是「从 (x,y) 走到
(x+dx, y+dy)」，dx/dy 为**有符号增量**（`UnpackSignedChar`）。服务端必须回
「起点 + 增量」；旧实现恒发 dx=dy=0 → 客户端每次被令走回原地 → 回弹。

遇怪触发点：服务端在收到 C2S_MAP_MOVE 后按需下发战斗帧（m4 用「每 N 次移动」触发）。

|---|---|---|---|
| C2S 点击 | 96 (C2S_NPC_LOOK) | id(4) | 〔B〕/〔C〕真机实发 |

| S2C 教招式列表 | 149 (S2CNpcLearnList) | mode(1) icost(2) + [skid(2) npcLimit(1) validLearn(1) freeLevel(1)]×n + skid=0 结束 | 〔B〕/〔C〕 |
| C2S 学招式 | 103 (C2S_NPC_LEARN_SKILL) | skid(2) | 〔B〕 |
| S2C 收购列表 | 148 (S2CNpcSellList) | mode(1) [+ticketid(4) 当 mode=2 / +country(1) 当 mode=3] + [shape(4) amount(2) price(4)]×n + shape=0 结束 | 〔B〕/〔C〕 |
| C2S 卖出 | 106 (C2S_NPC_SELL) | flag(1) + flag=1: itemid(4) / flag=0: pos(1) amount(2) | 〔B〕/〔C〕 |

**买卖（M10）**：`147` 开「买」面板（`dlgtrade.Show`），`148` 开「卖」面板（`dlgsellnpc.Show`），
两者是**两个独立窗口**，不要同时下发。`148` 的第一列是 **shape（造型）而非实例 id**——客户端拿它查
`itemdata` 取名，并去背包里按 `m_Shape` 匹配。

`106` 两种形态含义不同：`flag=1` 带**实例 id**，卖该实例整摞；`flag=0` 的 `pos` 是
**148 列表的下标**（不是背包格号，客户端按 `enumerate(m_Goods)` 发），`amount` 是件数。
所以服务端必须缓存自己发出去的那份清单；且清单**只许原位改件数、不许重排**，
否则会出现「点鹿茸卖成下一项」。收购价无真值来源（客户端 `itemdata` 只有名字/描述），
本服按售价 1/4 收，见 `m4_server.sell_price_of`。

**学招式（M9）**：`149` 一下发客户端就弹「学技能」面板（`dlglearnskill.CreateSkillInfo`），
不需要额外的开窗帧。面板上的**价格与经验由客户端本地算**（`LearnCostStd(level)` 等），
服务端只给三件事：能学哪些 skid、`validLearn=255`（走标准费用档）、`freeLevel`（该级及以下免费）。
学会的回帧是 `S2CSkillLevel(65)` 两帧：`sktype=2` 写 `g_Skills[ST_MAGIC]`（学会）、
`sktype=7` 写 `ST_MAGICREADY`（进战斗菜单）——**少发第二帧就是「学会了但打不出来」**。

### 对话文本语法（`dlgnpc.ParseWord1`）
msg 按行解析，行首字符决定类型：
- `P` = 新页头（`P(npcicon,npcname)` 指定头像/名；`P...H` 玩家侧；`P...R` 本页带 response）
- `Q`/`L`/`M`/`R` = 选项（flag 0/1/2/3），`Q选项文本`；选项序号（1 起）即回给 `C2SNpcAnswer` 的 i
- `D(n)` = 延时选项；`X` = 退出文案；其它非空行 = 正文

最小对话示例：
```
P
你好，我是村长。
Q我想接个任务。
Q没事，随便看看。
```
客户端显示一页正文 + 两个选项；点击选项 1 → `C2SNpcAnswer(1)` → 服务端回下一段 `S2CNpcChatExt`。

### 3.1 `S2CWarWState`(123) 位域与 `hp_chg` 符号

**证据构成**：位序〔A〕（`mxmain.dll:0x41A4D0` 反汇编，`mask |= 0x80 >> (off+i)`）+ 字段顺序〔B〕
（`src/netwar.py:S2CWarWState`）+ 行为分支〔B〕（`war.State` / `warrior.BeginHit` / `CreateModifyHP`）。
**没有**〔C〕级「渲染外观逐帧校准」——`hp_chg` 的飘字外观仍待真机专项实测（见 §6.2）。

`src/netwar.py:S2CWarWState` 的三个 `UnpackBit` **共享同一个字节**：

```python
cmd.id    = netobj.UnpackInt(1)
cmd.hurt  = netobj.UnpackBit(0, 4)   # bits[0:4]  伤害表现
cmd.life  = netobj.UnpackBit(4, 2)   # bits[4:6]  生死状态
cmd.ward  = netobj.UnpackBit(6, 2)   # bits[6:8]  受击姿态
cmd.hp_chg= netobj.UnpackInt(4)      # 有符号 4B
```

★ **`UnpackBit` 的偏移从最高位开始数**（`off=0` → bit7）〔A：`0x41A4D0` 的
`mask |= 0x80 >> (off+i)`，`(byte & mask) >> (8-n-off)`〕，所以线上字节是
`(hurt<<4) | (life<<2) | ward`——**高 4 位 hurt、中 2 位 life、低 2 位 ward**。
换算时别按 LSB 拆：`0x11` 是 `hurt=1, life=0, ward=1`（会心 + 受击），
不是 `hurt=1, life=1, ward=0`。
解码写法：`hurt=(bf>>4)&0xF; life=(bf>>2)&0x3; ward=bf&0x3`。

**取值表**（`src/core/war.py:7-16`）：

| 字段 | 值 | 含义 | 客户端行为 |
|---|---|---|---|
| `ward` | 0 NONE | 无姿态 | ★ `warrior.BeginHit()` 落入 `phy and not bprotect` ⇒ **走 `Evade()` 演成闪避** |
| | 1 HIT | 受击 | `Hit(False)` → 受击动画 + `PlaySound('hit')` |
| | 2 DEFEND | 防御 | `Hit(True)` → 防御动画 |
| | 3 EVADE | 闪避 | `Evade()` |
| `hurt` | 0 NONE | 普通 | `CreateModifyHP` 用 `war\hit\` 数字 |
| | 1 BS | 会心 | 用 `war\shit\`（带 `eff.spr` 特效） |
| `life` | 0 NORMAL | 正常 | — |
| | 1 INSENSIBLE | 不省人事 | — |
| | 2 DEAD | 死亡 | ★ **只有 ==2** 才走 `obj.Die()` 播死亡动画 |
| | 3 DEL | 删除 | — |

**`hp_chg` 符号：正数 = 扣血，负数 = 回血**〔B：三条互相独立的源码证据；本条**无**〔A〕/〔C〕〕：

1. `src/core/war.py:State` 直接把 `cmd.hp_chg` 交给 `obj.CreateModifyHP(...)`，且
   `if cmd.hp_chg < 0 and obj.m_State == 'die': obj.Guard()` —— 负数被当成「从倒地拉回」（回血）。
2. `src/core/warrior.py:CreateModifyHP`：`hp >= 0` → `war\hit\`/`war\shit\`（伤害数字）；
   `hp < 0` → `war\hp\`（回血数字）。
3. 官方自带战斗测试台 `src/testwar.py` 全部伤害样例均为**正数**：
   `State(11, WARRIOR_WARD_HIT, …, 330)`、`100`、`934`、`101`；
   `src/card_game.py` 同向：`if hp: cmd.ward = 1 else: cmd.ward = 3` + `cmd.hp_chg = hp`（伤害为正），
   回血 `DoAddHp` 用 `cmd.hp_chg = -hp` 且 `ward = 0`。

> ⚠ **M4 旧实现的错误**：曾发 `ward=0` + `hp_chg=-50` + `life=0` 恒定。
> 三者叠加的后果是——敌方演**闪避**（不播打击特效）、飘的是**回血**数字、击杀时**不播死亡动画**。
> 这解释了 M4 文档 §6.1 记的「⏳ hp_chg 显示值：发 -50 客户端飘 18」——
> 录像里的大数字其实是**倒计时**，不是伤害飘字（见 `data/m4_calib/sheet_dmg.png`）。

**`S2CWarHPPercent`(125) 只对友方发**〔B 代码分支 / C 实测抛错被 `war.Process` 吞掉〕：
客户端 `war.HPPercent` 直接调 `obj.m_HPFull.SetRate(...)`，
而 `m_HPFull` 仅在 `warrior.Create` 的 `if allied or war.g_WarScene == 65535` 分支创建
（`src/core/warrior.py:1602`）——**敌方单位没有血条对象**，对敌方发本帧会抛 `AttributeError`。

### 3.2 统一伤害示例（★唯一口径，§3.3 / §5 / §6 / §7.2 一律引用本块）

设定：主角 `id=0` 普攻敌方 `id=1`。位域字节一律按 `bf = (hurt<<4)|(life<<2)|ward` 计算。

| 场景 | hurt | life | ward | `bf` | `hp_chg` | 客户端表现 |
|---|---|---|---|---|---|---|
| 普通命中，未死 | 0 | 0 | 1 | `0x01` | `+50` | 受击动画 + `war\hit\` 橙字「50」 |
| 普通命中，击杀 | 0 | 2 | 1 | `0x09` | `+80` | 受击 + 橙字 + `obj.Die()` 死亡动画 |
| 会心，未死 | 1 | 0 | 1 | `0x11` | `+120` | `war\shit\` 红字 + `eff.spr` |
| 会心，击杀 | 1 | 2 | 1 | `0x19` | `+200` | 红字 + 死亡动画 |
| 回血（对照，**不是**伤害） | 0 | 0 | 3 | `0x03` | `-30` | `war\hp\` 蓝字；`card_game.DoAddHp` 用 `ward=3`，且回血一般单独发、不带攻击演出 |

帧序列（攻击者 → 目标）：

```
普通一击（造成 50）：
  117 AttackNormal        att_id=0 vic_id=1
  123 WState              id=1 bf=0x01 hp_chg=+50      ← 受击、扣血 50、存活
  119 AttackNormalEnd      id=0
  114 WarTurn              lastcmd=0                     ← 交还操作权（清「请等待」）

会心击杀（造成 200）：
  117 AttackNormal        att_id=0 vic_id=1
  123 WState              id=1 bf=0x19 hp_chg=+200     ← 会心、扣血 200、life=2 死亡
  119 AttackNormalEnd      id=0
  116 WarDel              id=1

```

敌方回合打主角（两条通道，别混）：

```
  123 WState     id=0 bf=0x01 hp_chg=+dmg    ← 只负责「飘字 + 受击表现」
  125 HPPercent  id=0 per=剩余百分比          ← 友方才有血条对象
```

> `ward=0` → 演**闪避**、不播打击特效；`life≠2` → 击杀**不播死亡动画**。

#### 3.4.1 ★ 两个反直觉点（先记住，别按「参数名」猜线序）

1. **169 的 `id` 参数不上线**：`C2SWarSummPerform(id, target, perform)` 的函数体只写

## 5. 易错点

> 每条末尾标等级：「A 原生层 / B 源码 / C 真机 / D 推导」。同一句里混级别时取最低那档说明适用范围。

1. **C2S/S2C 帧格式不对称**〔C〕：C2S 是 `opcode 在前 + 长度不含 opcode`，S2C 是 `长度在前 + 长度含 opcode`。
   别把 S2C 的收包逻辑外推到发送方向（M1 旧版就是这么错的，见 M1 §1.3）。
2. **变长字符串必须 `\0` 结尾、无长度前缀**〔C〕（2026-10-15 实测修正）：
   旧 `[1B len]` 前缀字节被客户端渲染为名字前的「口」（截图实证「口南遥国」「口野猪」）；
   且 name 无 `\0` 时客户端越界读**吞掉后续帧字节**，WarTurn 无法到达 → 战斗永久卡「请等待」（wait.igs 羽毛动画）。
3. **S2CWarAdd 的 desc** 先发空 desc（单字节 0），避免变长解析错位〔B〕。
4. **S2CWarAdd 的 bitfield** 是 1 字节，且按 **MSB-first** 读：bit7=allied / bit6=type / bit5=child
   〔A：`0x41A4D0`；B：`UnpackBit(0,1)/(1,1)/(2,1)`；写 `0x80` 才是「我方」〕。
   旧文档写成 bit0/bit1/bit2 是错的。
5. **S2CWarWState 的 bitfield** 是 1 字节：**高 4 位 hurt / 中 2 位 life / 低 2 位 ward**
   （即 `bf = (hurt<<4)|(life<<2)|ward`；`0x11` → hurt=1 life=0 ward=1），hp_chg 是**有符号 4 字节**〔A 位序 /B 语义〕。
   ★ **`ward` 必须为 1(HIT) 才是「受击」**；`ward=0` 会被 `BeginHit()` 判成 `Evade()` 演闪避〔B〕。
   ★ **`hp_chg` 正数 = 扣血**（负数 = 回血）；击杀时 **`life` 必须为 2(DEAD)** 才播死亡动画〔B〕。
   ★ **`HPPercent`(125) 只对友方发**（敌方无 `m_HPFull` 血条对象，会抛 AttributeError）〔B〕。
   **具体数值一律照 §3.2 统一示例**（旧文本把 hurt/ward 的位位置写反，已修正）。
6. **S2CNpcChatExt 的 name 是定长 20**、**S2CTaskAdd 的 name 是定长 26**〔B〕，不足补 `\0`（定长不需要 `\0` 结尾）。
7. **S2CWarStart 的 scene 字段 = 客户端 scene - 1001**〔B〕（客户端读时 `UnpackInt(2) + 1001`）。
8. **战斗录像弹窗是正常现象**〔B〕：客户端默认 `g_RecordWar=True`，WarStart 时弹「现在处于游戏录像中」，不影响战斗。
9. **招式帧不可省**〔B＋C 录像复核〕：收到 `C2SWarPerform`(161) 必须回 `S2CWarPerform`(122)，
   不能拿 `S2CWarAttackNormal`(117) 顶替 —— 客户端的 `war.Perform` 命令**只由 122 创建**。
10. **战斗指令必须逐条回应**〔B＋C〕：客户端的「请等待」只在收到 `WarTurn`(114) 或 `WarEnd`(113) 时清除。
   服务端对任何一条战斗指令（道具/召唤/保护/特技/捕捉…）不作回应，都会让客户端**永久**卡在「请等待」。
11. **`WarEnd` 后需重发场景**〔B＋C〕：客户端 `war.WarEnd` 会 `world.ClearAllObject()` 且不自行请求场景，
    服务端应补 `SceneM(96)+AddNpc(99)+GotoM(97)`，否则地图空/战斗单位残留。
12. **`WarStart` 不可重复下发**〔B〕：客户端 `g_WarTimes` 只增不减地配对，`WarEnd` 在 `g_WarTimes == 0` 时被直接丢弃。
13. **`PropInit` 不含末 8 项属性**〔B，2026-10-15〕：`hero.CreateProp` 只解 `ITEM_ALL[:-8]`，
    5 项抗性 + `m_At`/`m_Df`/`m_Dp` 必须由 `S2CPropResist(18)`/`S2CPropPower(19)` 下发；
    否则它们保持 `Default()`=0，导致 `hero.GetMagicData` 判定几乎所有招式 invalid →「无法使用这个招式」。
14. **装备招式要用 `S2CSkillLevel`(65) 的 `sktype=7`**〔B〕，不是 `S2CBlock`(77)：
    战斗菜单读 `g_Skills[ST_MAGICREADY]`（索引 6），而 `UpdateSkill` 会 `sktype -= 1`；
    `S2CBlock`→`S2CMagicInfo` 只更新技能面板 UI，**不会**让招式出现在战斗菜单里。详见 §7.1。
15. **敌方回合必须先发 `WarTurn`**〔B，2026-10-15〕：`war.AttackNormal`/`Perform` 开头有
    `if g_Turn == 0: return`，且 `g_Turn` 只由 `S2CWarTurn` 自增；不发开场 WarTurn 则演出全部被跳过。

### 7.1 进世界序列（新增 3 帧）

```
① 收 C2SLoginPlayerEnter(id)  opcode=2
② S2CPropInit(16)             id + 67 项属性（m_HP/m_HPMax = 400）
③ S2CPropResist(18)           5 项抗性各 1B 有符号（m_Resist_Xian/Gui/Yao/Zhi/Nian）
④ S2CPropPower(19)            m_At/m_Df/m_Dp 各 1B（本服给 100）
⑤ S2CSkillLevel(65) sktype=2  授予招式（skid(2) sklevel(1) bid(2) point(2) cash(4) iHighLv(1)）
⑥ S2CSkillLevel(65) sktype=7  **装备**招式进战斗菜单（只读 skid(2) + sklevel(1)）
⑦ S2CMapSceneM(96) → S2CMapAddNpc(99) → S2CMapGotoM(97)
```

**为什么 ③④ 不能省**：`hero.CreateProp` 只解 `ITEM_ALL[:-8]`；末 8 项仅被设为 `Default()`=0，
而 `hero.GetMagicData` 用它们做可用性判定 ⇒ 不发就报「无法使用这个招式」。

**为什么 ⑥ 必须用 sktype=7（易错点）**：战斗菜单读 `hero.g_Skills[ST_MAGICREADY]`（索引 **6**），
而 `hero.UpdateSkill` 开头执行 `sktype -= 1` ⇒ 要让索引落在 6 **必须传 7**。
- ❌ `S2CBlock(77)` → `S2CMagicInfo` 只调 `block.UpdateBlockInfo`（技能面板 UI），**不装备**；
- ❌ `sktype=2` 只把招式学进 `g_Skills[ST_MAGIC]`（索引 1），同样不进战斗菜单。

### 7.2 敌方回合〔B：`war.AttackNormal`/`Perform` 的 `g_Turn` 门槛 + `warui` 的「请等待」清除点；C：真机回合能推进〕

```
玩家指令（攻击160/招式161/防御163）→ 演出帧 → 敌方回合
敌方回合: WarTurn(114)                      ← 开场：客户端 g_Turn += 1，否则演出被 `if g_Turn == 0: return` 跳过
          每个存活敌方: AttackNormal(117) → WState(123, 打主角) → HPPercent(125) → AttackNormalEnd(119)
                        → PropChange(17)    ← 主角真实血量走 PropChange，不是 WarWState
          WarTurn(114)                      ← 收尾：交还操作权（lastcmd=0 → warui.ShowHeroMenu）
```

打主角那一帧的**具体数值**（与 §3.2 同一口径，勿另编）：

```
123 WState     id=0 hurt=0/1 life=0 ward=1 hp_chg=+dmg   ← 只做飘字/受击表现
125 HPPercent  id=0 per=<剩余百分比>                      ← 只对友方
17  PropChange type=16 value=<剩余HP 2B>                  ← 真实血量
```

**主角掉血用 `S2CPropChange`(17)**：帧体 `type(1) + value`；`ITEM_ALL[16]` = `m_HP`（TWORD，2B）。
`src/nethero.py:S2CPropChange` → `hero.PropChgCheck` + `setattr(hero.g_Prop, 'm_HP', value)`。

★ `value` 的**宽度是 type 的函数，不是常量**：客户端按 `ITEM_ALL[type].Unpack()` 读，所以
1B（TBYTE：m_At 72 / m_Df 73 / m_Dp 74 …）、2B（TWORD：m_HP 16 / m_MP 18 / m_FP 20 …）、
4B（TDWORD：m_Exp 8 / m_NextExp 9 / m_Gold 43 …）、8B（TLONG：m_Cash 6）都存在。
完整 75 项见 `服务端源码/sim/tap.py:_ITEM_ALL_SPEC`（源自 `src/hero.py:ITEM_ALL`）。

**战败**：主角 HP ≤ 0 → 逐个 `WarDel(116)` 清场 → `WarEnd(113)` → 场景重同步。
