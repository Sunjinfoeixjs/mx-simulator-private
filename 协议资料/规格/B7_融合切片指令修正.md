## 二、P4：函数内全局赋 None 的前置 LOAD_GLOBAL（4 文件）

多益 VM 对函数内 `g_X = None` 编译为 **`LOAD_GLOBAL g_X; LOAD_CONST None; STORE_GLOBAL g_X`** 三连
（标准 CPython 2.6 仅 `LOAD_CONST None; STORE_GLOBAL g_X`，无前置 LOAD_GLOBAL）。

- 证据：`dialog/dlg_wclock_unlock.py::CloseWindow` 观测字节
  `0x61 3; 0x8F 0; 0xC4 3`（LOAD_GLOBAL g; LOAD_CONST None; STORE_GLOBAL g）。
- 修复：`u6_patch26.py` P4——`assign ::= LOAD_GLOBAL expr store` + n_assign 丢弃前置读取。
- 解锁：`dlg_wclock_changew/setup/unlock`、`dlgquiz`（4 文件）。
- 全语料仅 4 处，均在此 4 文件。

## 三、P5：循环内局部赋常量的前置 LOAD_FAST + POP_TOP（3 文件）

多益 VM 对循环体内 `x = <const>` 编译为
**`LOAD_FAST x; LOAD_CONST <const>; POP_TOP; STORE_FAST x`**（LOAD_FAST 压入旧值被 POP_TOP 丢弃）。

- 证据：`netopenui.py::S2CShowSummonInfo`、`teamui.py::SetLineup`、
  `dialog/dlggroup.py::__init__/OnChgGrant` 观测字节。
- 修复：P5——`assign ::= LOAD_FAST expr POP_TOP store`。
- 解锁：`netopenui`、`teamui`、`dlggroup`（3 文件）。

## 四、★ B7 核心：融合切片指令（5 文件）

### 4.1 重大发现：0x28-0x2B / 0x48-0x4B 并非 CALL_FUNCTION 族

opmap 表长期把这两组 8 个 opcode 记为「变参调用族」（CALL_FUNCTION_VAR_KW 等）。
B7 逐行核对反编译 `dll/export/decompiled_all.c`，**彻底推翻**：

- `case 0x2b`（行 129370）与 `case 0x4b`（行 129565）**共用同一条 slice 逻辑**：
  - `(uVar15 & 2)` → 弹 step（无则 None）
  - `(uVar15 & 1)` → 弹 stop（无则 None）
  - 随后调 `FUN_0048c2d0` → `FUN_00484290`（报错串 `'%.200s' object does not
    support item deletion`）或 `FUN_004834f0`（报错串 `'%.200s' object doesn't
    support slice deletion`）。
- **语义**：
  - `0x28-0x2B` → `del obj[a:b(:c)]`（BUILD_SLICE + DELETE_SUBSCR 融合，弹 1-4 推 0）
  - `0x48-0x4B` → `obj[a:b(:c)] = v`（BUILD_SLICE + STORE_SUBSCR 融合）
- **栈布局与标准不同**（多益为融合重排）：删除族 `[obj, start, stop?, step?]`；
  赋值族 `[value, obj, start?, stop?, step?]`（value 在栈底）。
- 全语料仅 9 处（极稀有，故历史误判从未暴露）：
  `ntpath::normpath`(0x2B×1)、`interface::DeleteSelected`(0x2B×2)、
  `warnings::resetwarnings`(0x48×1)、`dlgriderefine::__init__`(0x49×2, 0x4B×2)、
  `sre_compile::_optimize_unicode`(0x4B×1)。

### 4.2 展开方案（tools/expand_slices.py）

由于融合指令无标准 1:1 对应，且改变指令长度，需**展开为标准序列 + 重算偏移/跳转/lnotab**：

- 删除族 `0x2B`：`BUILD_SLICE 2; DELETE_SUBSCR`（栈 [obj, start, stop] 直接可用）
- 赋值族 `0x4B`：`BUILD_SLICE 2; STORE_SUBSCR`（value 在栈底，token 序 value 在前，
  由语法补丁 P6 `store_subscript_rev` 在语义层反转输出 `obj[:] = value`）
- 缺失边界补 `LOAD_CONST None`
- **偏移重算**：观测偏移 → 新标准偏移映射；绝对跳转（0xA2）与相对跳转
  （0xE5/0xB7/0xE3/0xCD/0xCF/0xD3/0xD6）目标同步修正。
- lnotab 保持原样（展开多在函数尾部，行号启发式影响可忽略）。

### 4.3 语法补丁 P6（u6_patch26.py）

赋值族 token 序 value 在前，uncompyle6 标准 `store_subscript ::= expr expr STORE_SUBSCR`
无法匹配，补：

```
store ::= store_subscript_rev
store_subscript_rev ::= expr build_slice2 STORE_SUBSCR
```

n_assign 覆盖：检测 `store → store_subscript_rev`（store 包裹一层），输出
`obj[:] = value`（`rev[0]` + `[` + `rev[1]`(build_slice2 边界) + `] = ` + value）。
实测还原：`warnings::resetwarnings` → `filters[:] = []` ✓

### 4.4 解锁

`ntpath`、`interface`、`warnings`、`sre_compile`、`dlgriderefine`（5 文件）。
其中 ntpath/warnings/sre_compile 是 Python 2.6 标准库（游戏内嵌），interface/dlgriderefine
为 UI 模块。

## 五、剩余失败：dialog/dlgsysopt

唯一剩余。根因非融合指令（fuse=0）：模块级与各子函数**单独 parse 均 OK**，
但 `decompile_file` 整体流程失败（语义 deparse 阶段 SourceWalkerError，
错误栈显示 `_ifstmts_jump` 归约）。疑为模块级 MAKE_FUNCTION 与嵌套 code 的
code_objects 传递问题，或某函数在共享 scanner 状态下 parse 失败。
留待 B8 专项排查。

## 六、方法回顾

1. **反编译实证优先**：opcode 语义争议一律回 `decompiled_all.c` 逐 case 核对，
   报错字符串（"item deletion" / "slice deletion"）是铁证。
2. **全语料统计定位稀有 opcode**：0x28-2B/0x48-4B 全语料仅 9 处且全部集中在
   失败文件——统计学上即根因。
3. **栈布局推演**：从融合指令前的压栈序列还原 [value, obj, start, stop] 布局，
   设计标准序列展开 + 语法反转。
