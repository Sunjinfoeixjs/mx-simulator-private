## 阅读指引：5 分钟速览

> 给第一次打开这份文档的人。读完这一节你能回答三个问题：**这是个什么东西、
> 它凭什么能跑、我该从哪一节开始读**。不想读全文就只看这 5 屏。

### 一句话

原版《梦想世界2013》客户端（内嵌 Python 2.6）**不知道服务端是假的**——它只认 TCP 上的
私有协议。本项目把「原版服务端该回的字节」按客户端 `Unpack*` 的线序重新拼出来，
于是客户端原封不动也能登录、走路、打怪、升级。

```
mx.exe（原版，只改了 1 字节） ──TCP──▶ 自研模拟服（Python 3，纯标准库）
                                            │
                                            └─ 存档 role_<账号>.json
```

### 五个必须知道的事实

| # | 事实 | 一句话解释 |
|---:|---|---|
| 1 | **客户端只改了一个字节** | `mxmain.dll` 的 `+0x72`（加密开关）改成 0，走明文。其余二进制原封不动，不 hook、不打补丁 |
| 2 | **协议是私有二进制** | S2C 是 `[长度][opcode][data]`，C2S 是 `[opcode][长度][body]`——**两头字节序相反**，这是第一个坑 |
| 3 | **线序有三方必须对齐** | 服务端 `build_*` 写、调试台 `OVERLAY` 读、客户端 `Unpack*` 读。任一方漂移就会「读错位但不报错」 |
| 4 | **顺序就是契约** | 进世界帧序、战斗帧序、`_dispatch` 分支顺序……错一帧就是「卡请等待 / 地图全空 / 打不动」 |
| 5 | **真值和模拟参数必须分清** | 地图/掉落/招式表是真值；经验曲线/收购价/材料配方是模拟。§10 逐条标注。**特别地：默认物伤模型 `reverse` 的公式形状有反编译出处，但 A/D/P/Lt 映射仍是模拟参数**（§7.5.2） |

### 读这份文档的正确姿势

- **本文只写符号名、不写行号**。行号漂移维护成本太高；符号是否仍存在、§17 表是否同步、手写指标值是否与实况一致，由 `_check_anchors.py`（三向体检）守着。
- **不要跳着改 `_dispatch`**。它是一串顺序敏感的 `if/elif`，插错位置**不报错**，
  只表现为帧序错误。插入位置由 `DISPATCH_PRE_WAR_OPS` 与 `tests/_test_dispatch.py` 守着。
- **看到「模拟参数」不要当成 bug**。原服已停服、真值不可得的地方，文档会明写。

## 术语表

> 按「第一次读会卡住」的顺序排，不是字母序。每条都给**它在代码里长什么样**——
> 本项目大量术语是边做边造的，光看中文名对不上代码。

### 协议与字节

| 术语 | 含义 | 代码位置 |
|---|---|---|
| **C2S / S2C** | Client→Server / Server→Client。opcode 常量都带这个前缀 | `OP_*` / `C2S_*` |
| **opcode** | 报文里的「指令号」，1 字节。S2C 路由表在客户端 `net.py` 的 `NET_FUNCTION_NAME` | `net.py` |
| **帧 / 分帧** | 一段完整报文。**C2S 与 S2C 的帧头字节序相反**，最容易踩 | `make_s2c` / `recv_c2s` |
| **裸区（Bare 25B）** | Hello 之后客户端回的 25 字节**没有帧头**，分帧器必须特殊跳过 | `hello_response`、`tap.feed` |
| **`var_gbk` / C 字符串** | 变长串 = GBK 字节 + `\0`，**无长度前缀**。与「1B 长度前缀」是两种线序，混用会吞帧 | `var_gbk` |
| **UnpackDesc** | 带标签联合的描述串，**不是** C 字符串。空值是单字节 `0x00` | `_OV_NOTE` 48/98/99/106 |
| **位域（bitfield）** | 一字节塞多个标志，本作是 **MSB-first**（bit7 起） | `WarAdd.allied`=`bit7`、`WState` |

### 服务端架构

| 术语 | 含义 | 代码位置 |
|---|---|---|
| **内核 / `M4Server`** | 游戏服务端本体：连接、分派、战斗状态机、存档 | `m4_server.py` |
| **`_dispatch`** | 一条上行指令的总分派，**顺序敏感的长 if/elif** | `_dispatch` |
| **战斗保底** | 链尾 `elif self.in_war:`，把没做逻辑的战斗指令也回一帧 `WarTurn` | `_fallback_turn` |
| **`DISPATCH_PRE_WAR_OPS`** | 「必须排在战斗保底之前」的 opcode 契约表，58 条 | 同名常量 |
| **`build_*`** | 组包函数族（58 个），每个对应一种 S2C 帧 | `m4_server.py` |
| **会话 / `MultiServer`** | 一个连接 = 一个 `M4Server` 实例；存档按账号分文件 | `MultiServer` |
| **`singleplayer.py`** | 宿主：起内核 + 劫持本地 HTTP + 改写客户端 ini + 托管 `mx.exe` | `singleplayer.py` |

### 战斗

| 术语 | 含义 | 代码位置 |
|---|---|---|
| **`WState`** | 受击表现帧（op123），位域里塞了 `hurt/life/ward` | `build_war_wstate` |
| **`ward`** | 受击姿态：1=HIT / 2=DEFEND / 3=EVADE。**造成伤害必须发 1** | 同上 |
| **`life`** | 生死位：只有 `==2` 客户端才播死亡动画 | 同上 |
| **`hp_chg`** | 血量变化，**正数=扣血**（不是回血） | 同上 |
| **`hurt`** | 会心（红字）标志，纯表现层，不改数值 | 同上 |
| **速度序** | 每回合按速度降序结算，出手顺序体现为**下发帧的先后** | `_speed_order` |
| **宠物挂起** | 主角交完指令后，服务端挂起等宠物指令（168-174）的第二段异步包 | `_resolve_hero_round` |
| **`WarTurn`** | 回合推进的唯一开关；客户端 `g_Turn==0` 时会忽略后续演出 | `build_war_turn` |

### 观测与回归

| 术语 | 含义 | 代码位置 |
|---|---|---|
| **`OVERLAY` / 覆盖表** | 调试台的 S2C 字段解码表，逐字段对齐 `build_*` | `tap.py` |
| **`_OV_DYN`** | 布局随内容变化的解码分支（op17/48/49/65/96/164 等） | `tap.py` |
| **`TappedConn`** | 鸭子类型的 conn 替身，零侵入拦截全部上下行字节 | `tap.py` |
| **三角一致性** | `build_*` ↔ `OVERLAY` ↔ 客户端 `Unpack*` 三方对齐 | §2.4 |
| **文档三向体检** | A：文档引用的符号是否存在；B：§17 表是否与源码一致；C：手写指标值与 STATS/源码实况一致 | `_check_anchors.py` |
| **§17 生成** | 扫描 `build_*` / 常量 / `class *` / 关键方法，生成符号索引 | `_gen_anchor_table.py --write` |
| **误报闭环** | 探针仍报「未识别」时自动加长 body / 进战斗重试 | `coverage_smoke.py` |
| **轮次标记（round）** | 每批帧打一个轮次号，只取「这批里新出现的未识别」，并可撤销已证伪的误报 | `tap.FrameTap.mark_round` / `unknown_since` / `forget_unknown` |

### 真值相关（最容易误解）

| 术语 | 含义 |
|---|---|
| **真值** | 从客户端数据/反编译/录像**实证**得到的值，标注了来源 |
| **模拟参数** | 原服已停服、真值不可得，由本项目**约定**的值（如经验 60/只、收购价 1/4） |
| **半真值** | 有实测支撑但样本不足（如速度/会心率，见 §7.4） |
| **欠定** | 数据不足以唯一确定参数（如物伤公式的 `A/D/P/Lt`，多个点都能拟合） |
