# 《梦想世界》客户端安装分析 —— `D:\mxsj2013`

> 分析对象：`D:\mxsj2013`（用户提供的**工作/改副本**安装，非官方标准安装位 `D:\多益网络\梦想世界`）。
> 目标：厘清目录结构、关键二进制、已抽取脚本与配置，并与既有逆向工作（server.ini 解码 / 协议研究 / opcode 字段拆解）对上号。

## 0. 结论速览

- 这是一份**完整可运行**的游戏副本，且已做过资源抽取：内含 `client/`（安装）与 `decoded/script/`（485 个已抽出的 marshal 脚本模块）。
- **版本**：客户端 **1.1.51**（`client/patch/patch_1.1.51.dat` + `mx.bin`）；各二进制构建于 2012 下半年（`mxmain.dll` 2012-11-07、`mx.exe` 2012-08-30），属 2012/2013 时代客户端，与本项目逆向时间线吻合。
- **协议源码已就绪**：`decoded/script` 下 485 个 `.bin` 均为 Python 2.6 marshal 代码对象（首字节 `0x63`），其中 58 个含 `PacketPrepare`、62 个含 `g_Net`、含 `C2S_WAR_ATTACK` 等——网络/协议层代码完整在此，即此前 `netwar.py`/`netitem.py` 等逆向素材的「哈希命名」抽取版。
- `client/server.ini` 即我们已全量解码的服务器列表（6 区 205 服，`mx.ini` 刷新时间戳 1791844025≈本轮会话），说明该副本的 server 列表是经我们解码产物刷新的。

## 5. `decoded/script/` —— 485 个 marshal 模块（协议逆向核心）

- **命名**：`<4位序号>_<8位哈希>.bin`（如 `0001_008CED9E.bin`）。哈希为原模块名指纹，故 `netwar`/`netitem` 等以哈希名存在；此前工作区以 `net*.py` 原名副本引用同一批素材。
- **格式已验证**：前 16 字节均为 `63 00 00 00 …`（`0x63` = marshal `c` 代码对象签名），可直接用 `pymarshal26` + `opmap` 反汇编——与 `dissect_combat.py`/`dissect_itempet.py` 的输入格式完全一致。
- **协议代码存在性（grep 实证）**：
  - 含 `PacketPrepare`：**58** 个
  - 含 `g_Net`：**62** 个
  - 含 `C2S_WAR_ATTACK`：**1** 个（战斗模块在列）
- 因此 `dissect_combat` / `dissect_itempet` 工具链**可直接喂这些 `.bin`** 继续深挖（无需再依赖工作区副本）。

## 6. 与既有逆向工作的关系 & 下一步

**已对齐**：
- `server.ini` 解码产物 ↔ 本副本 `client/server.ini`（同一份）。
- 协议字典 / opcode 字段拆解（netwar/netitem/...）↔ `decoded/script` 中的 marshal 模块。
- `live_testbed.py` / `game_loop_demo.py` 的握手与参考加密层 ↔ `mx.exe`+`mxmain.dll` 的主链路。

**“运行游戏边改”落地路径**：
1. **改 server.ini 指本地服**：把 `client/server.ini` 指向 `live_testbed.py` 起的 mock 后端，可验证客户端能否走完 Hello→SetSeed 握手（明文段能过；加密段因 VMProtect 算法未还原会卡在登录）。
2. **改协议逻辑**：需对 `decoded/script` 中目标 `.bin` 反编译→改 Python→重编译 marshal→重新封包回客户端；`dissect_*.py` 已具备反汇编能力，可扩展为反编译/重编译。
3. **解密资源**：用 `serverini_sim.py` 的 ADD-9 层解密 `data/*.fls`。

**仍未攻破**：
- `mxmain.dll` `0x43cc50`（VMProtect 虚拟化流密码）—— 真实客户端↔自建服互通的唯一阻塞点（需动态调试/脱壳）。
- `data/*.fls` 资源明文（待 ADD-9 解密）。
