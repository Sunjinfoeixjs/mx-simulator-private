## 二、保护机制（多益的混淆体系）

这次逆向最大的发现是这套客户端的**四层脚本保护**：

```
script.fls (0SLF 容器)
  └─ 每个条目: zlib 压缩流 (0x78DA 开头)
       └─ 解压后: Python 2.6 marshal 序列化的代码对象
            ├─ 每个条目独立 XOR 密钥（首字节即密钥，0x69/0x46/0x04...）
            ├─ 条目内部还有**分段密钥轮换**（零字节段统计发现 ≥5 种子密钥）
            └─ 字节码使用**重映射的自定义 opcode**（非标准 CPython 2.6）
```

- marshal 结构完好（函数名、变量名、字符串常量、文件名全部可读）
- 字节码指令集被替换：标准 CPython 2.6 的 opcode 表被定制，`0x8f/0xe0` 等指令与官方不对应——这是当年网易系/多益系端游标志性的防反编译手段
- 破解路径：用 Ghidra 逆向 mxmain.dll 中定制的 `PyEval_EvalFrame` 解释器循环，提取 opcode 映射表后即可完整反编译

## 三、.fls 资源容器格式

```
偏移      内容
0x00      魔数 "0SLF" (4B)
0x04      条目数 uint32 (script.fls=485)
0x08      校验/哈希字段 uint32
0x0C      稀疏哈希索引区（大量零填充 + 20 字节 SHA-1 级别的条目校验值）
...       条目数据区：zlib 流顺序存储，条目间有零填充 + 20 字节元数据
```

实际解包无需索引：按 `0x78DA` 魔数扫描 + zlib 流自校验即可 100% 切分条目（工具：`extract_scripts.py`）。  
15 个 fls 包按内容分类：char(角色 676MB)、interface(63MB)、magic(47MB)、map/mapobject、item、script、sound、skill、goods、war、minimap、misc、passive、effect。

## 五、服务器列表（server.ini：已破解 · server7.txt：未破）

> 下文的加密链针对 **`server.ini`**（客户端本地服务器列表），已完全破解。
> **`server7.txt`（更新器拉的远端列表）格式不同**（`-1` + zlib + 内层密文），
> 目前**尚未破解**，仅确认其周期同为 GCD=9。

### 5.1 加密链（经逆向确认）

```
磁盘文件 server.ini:
  [4 字节头] + zlib( marshal_string( 密文payload ) )

密文payload = 明文(游戏私有打包记录)  XOR  9 字节周期密钥  b'\x00{pohkhop'
                                              (hex: 00 7b 70 6f 68 6b 68 6f 70)
```

**密钥的恢复方法**：明文中的 `=` 分隔行（连续 9 个 `=`）经 9 字节密钥循环加密后，在密文里形成固定周期指纹  
`=FMRUVURM`（即 `0x3d ^ key[i]`，i=0..8）。定位该指纹 → 反推 `key[i] = cipher[i] ^ 0x3d` → 得到完整 9 字节密钥。  
该密钥对整段 payload 连续循环 XOR 即为逆运算（XOR 自反，无相位问题）。

> 注：旧报告推测的 `B1B>FKKFFI37` 周期模板同样呈现 GCD=9 的周期，与本案 9 字节密钥自洽 —— server7.txt 极可能复用同一套加密（待该文件样本验证）。

### 5.2 明文记录格式（schema 取自脚本自身常量）

`selectserver.py`（`entry_460`，函数 #8 @0xe37）常量池直接暴露了记录字段：

```
format 串:  fieldname=%s servername=%s ip=%s port=%d proxy=%s
相关常量:  'fieldname' 'servername' 'ip' 'port' 'proxy'
           'netobj' 'proxyip' 'proxyport' 'iplst' 'AliasServerName'
解析流程:  misc.OpenFile → g_ServerIni.read → C_sys.RecordString
          → splitlines() → strip() → replace() → m_RecordServer(...)
```

**字段标记（明文中的二进制标签）**：

| 标记                 | 含义                                                 |
| ------------------ | -------------------------------------------------- |
| `Mj`               | fieldname（字段名）                                     |
| `mj` / `Mp` / `MH` | 其余字段（ip / port / proxy 等，标签位置随版本变化）                |
| `MJ<名称>P`          | **servername**（服务器名，紧跟 2–4 个 GBK 汉字，以 `P`=0x50 终止） |
| `=` × 51           | 大区/分组分隔符（等价于脚本常量 `'======================'`）       |

`ip=%s port=%d` 表明 **IP 与端口在文件中以字符串/整数形式存放**，但外层 XOR 之后其字段体仍呈混淆态 —— 说明它们经过**第二层字段级混淆**，最终由原生方法 `m_RecordServer`（mxmain.dll）还原。这是剩余的唯一未解环节。

### 5.3 已恢复成果

- **密钥**：`b'\x00{pohkhop'`（9 字节，周期循环）—— 可直接解密任意同版本 server.ini
- **解密器**：`decrypt_serverlist.py`（`server_decrypted.bin` → 明文）、`extract_server_records.py`（明文 → 结构化记录）
- **服务器名**：高置信 **13** 个 + 候选 **25** 个（如 `絬袝簢壗`、`钩彆虾搻`、`磝崿山簢`、`吔螠部娭`、`箊彼處瘲`、`矔园昦粏` …）。*注：这些名在明文里虽为合法 GBK，但字形生僻，结合 `AliasServerName` 常量判断游戏对显示名做了**字模/别名映射**，真实展示名需经该层还原。*

### 5.4 剩余环节（完成即可拿到真实 IP:Port）

1. 逆向原生 `m_RecordServer`（mxmain.dll）→ 还原字段级混淆，解出每个服务器的真实 `ip` / `port` / `proxy`。
2. 解析 `Z##G#` / `Z##A#` 类 token（如 `Z31G4Z#RVZ31A4`）与各 `Mj`/`mj` 字段体 —— 二者是 IP/端口最可能的承载者。
3. 应用 `AliasServerName` 别名表 → 拿到玩家可见的正式区服名。

## 六、地图格式（.map，81 张）

```
0x00   魔数 "0.1M"
0x04   宽度 uint32   (如 1001.map: 8000)
0x08   高度 uint32   (4200)
0x0C   块偏移表: ~450 个单调递增 uint32 偏移
...    图块数据: 每块以 "GEPJ0d" 开头 = 字节混淆的 JPEG（JPEG 倒写）
```

地图即大分辨率 JPEG 切片（8000×4200 像素），恢复方式：按偏移表切块，修复 JPEG 头字节序即可还原完整地图图像。
