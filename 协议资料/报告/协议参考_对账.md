## 3. 旧版提取器缺陷影响面（C）

### 3.1 缺陷描述

旧版 `extract_protocol_functions.py` 的常量正则为 `(C2S_\w+|GS2C_\w+)`，**不识别 `C2GS_` 前缀**。
遇到 `netobj.PacketPrepare(net.C2GS_ROLESALE)` 时匹配失败，退化为「取字符串中第一个数字」分支，
于是从 `C2GS` 中取到 `2` —— **所有使用 `C2GS_*` 常量的函数都被误判为 opcode=2**。

### 3.2 影响面

|---|---|
| 使用 `C2GS_*` 常量的函数数 | 117 |
| 涉及模块数 | 21 |

| 修正后落到正确 opcode 的函数数 | 117 |

涉及模块：`banword`、`dlgbeautycontest`、`dlgcalendar`、`dlgfindfriend`、`dlgfindteam`、`dlgfubenteam`、`dlggoodsellrecord`、`dlgjoinbeauty`、`dlgpeopleofyear`、`dlgpersonaccout`、`dlgreport`、`dlgserverbattle`、`dlguproom`、`findfriend`、`findteam`、`netbaike`、`netblog`、`nethero`、`netrichgood`、`netrolesale`、`netshop`

## 5. 结论与建议

1. **常量表缺口（已修）**：`protocol_map.json` 缺 18 个常量（17 个 `C2GS_*` + `C2S_TEXT`），
   已改以 `src/net.py` 常量表为权威来源（`tools/protocol/net_consts.py`），map 退为交叉校验。
2. **opcode 误判（已修）**：117 个使用 `C2GS_*` 的函数此前被误判为 opcode=2，现已落到正确编号。
3. **常量解析缺口（已修）**：模块自带常量（`marriage.C2S_MARRIAGE`、`dlgjingxiu.C2S_JingXiuInfo`、
   `dlgtitle.C2STITLECOLOR` 别名）此前解析不出 opcode，现已支持「模块局部 → net.py 全局」两级解析。
4. **模块覆盖缺口（已修）**：非 net 模块 68 个、协议函数 227 个此前完全不在参考内。
5. **路由表缺口**：map 的 `s2c_routes` 比 net.py 少 8 条；处理函数定位率已到 100.0%。
6. **仍待人工确认**：16 个函数 `PacketPrepare` 直传整数（见 §2.3），建议补进常量表；
   `protocol_map.json` 的 `c2s_opcodes` / `s2c_routes` 建议改为由 `net_consts.py` / `net_routes.py`
   从 `src/net.py` 生成，避免再次漂移。
