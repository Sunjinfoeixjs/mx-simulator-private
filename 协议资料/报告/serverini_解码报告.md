## 0. 一句话结论

server.ini 不是密码，是**三层打包的文本**：
`-1\r\n` 魔数 + zlib 压缩 + **模 256 加法 cipher（9 字节周期密钥）**，内层是 GBK 编码的服务器列表。
此前 17 轮 ip_probe 实验卡住，是因为一直按「XOR 密码」攻——实际是**加法 cipher**，换钥匙后一把过。

---

## 1. 三层结构（全部实测复现）

```
server.ini (4,414 B)
├─ 第1层 容器:  b'-1\r\n' + zlib 流
│    └─ 解压 → 8,977 B = [flag=0x73][len=8972 (4B LE)][payload 8,972 B]
├─ 第2层 编码:  payload[i] = (plain[i] + S[i % 9]) & 0xFF   ← 模256加法cipher
│    └─ S = [0, 9, 16, 21, 24, 25, 24, 21, 16]，即 S[p] = p × (10 − p)
└─ 第3层 文本:  GBK 编码，\r\n 分行（218 个），空白分字段，共 219 行
```

### 密钥推导（已知明文攻击）

- 原始 payload 在 2160/2213/8786 三处有 51 字节的重复图案 `=FMRUVURM`（9 字节周期）
- Python 侧 `ServerInfo()` 的常量 `'======================'`（22 个 `=`）提示：填充明文是 `=`
- 若为加法 cipher：`S[p] = pad[p] − '='` → `[0x00,0x09,0x10,0x15,0x18,0x19,0x18,0x15,0x10]`
- **验证**：用该密钥全量解码 → GBK 一次成功，输出合理 IP / 中文服务器名 / 端口

> 对比：此前按 XOR 攻（密钥 `\x00{pohkhop`）只能得到 `19N)# .)93L7$P` 类乱码结构；
> 同一段数据用加法密钥解出 `19.132.193.76 3134`——**算法定性错误是此前卡住的根因**。

## 4. 顺带修复：opmap 工具链的 STRINGREF 错位 bug

分析中发现 484 个脚本的反汇编名称大量错位（如 `Connect` 显示成 `.`）：
- **根因**：游戏 marshal 写入器的 refs 表**只登记字符串**（不含 code 对象），而读取器 `pymarshal26.py` 把 code 对象也加进 refs，导致所有 STRINGREF 索引偏移
- **修复**：`03_解密工具链/pymarshal26_fixed.py`（STRINGREF 按「仅字符串」子序列解析）
- **效果**：selectserver/misc/init/cfg 等脚本名称全部正确（`Connect/Refresh/CSearchServerListBox/AliasServerName/ServerInfo`…）
