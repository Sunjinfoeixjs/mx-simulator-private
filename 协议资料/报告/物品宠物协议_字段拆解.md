# 《梦想世界》物品 / 宠物 关键 C2S opcode —— 字段级逆向

> 方法：复用战斗拆解的栈模拟（`dissect_combat.sim_func`，已解决引擎自定义调用约定 + GBK bytes 解码），
> 扫描 scripts/ 全部 net*.py，按 `protocol_map.json` 模块归属提取属于「物品/宠物」子系统的发送函数。
> 字段结构（字节数/顺序）为反汇编实证；字段语义为基于结构与命名的推断（标注★）。

## 0. 总览与关键结构发现

- 覆盖模块：**5** 个（netitem / netpet / netstorehouse / netitemshop / netgoodsserver），拆解得到 **53** 个发送函数。
- **★ 命令族（multiplexed opcode）模式**：`netstorehouse`(op **71**) 与 `netitemshop`(op **89**) 是「单 opcode + 首字节子命令」族——
  同一下整数 opcode 承载数十种操作，第一个 `I:1` 字段即操作选择器（如 `C2SSHSetPwd`=op+旧/新两串 20B 密码；`C2SSetFight`=op+4B 召唤兽 id）。
- 对比：战斗 opcode(160-177) 是 **1:1**（一 opcode 一动作）；物品/宠物侧部分 opcode 走 **命令族**，需注意首字段语义。
- 4 字节(u32)字段用于物品 id / 召唤兽 id（量级 > 255）；1 字节(u8)多用于操作子类型或位置序号；密码/名称固定 20B 字符串（与登录密码同宽）。
- `S` 字段长度若为 `N:len` 表示**变长字符串**（实际长度由发送端动态计算）；`S:20` 为定长 20B。

| 模块 | opcode | 发送函数数 | 说明 |
|---|---|---|---|
| 物品(netitem) | 32,33,34,35,36,37 | 8 |  |
| 宠物(netpet) | 69,128,129,130,131,132,133,134 | 8 |  |
| 仓库(netstorehouse) | 71 | 16 | （命令族） |
| 物品商店(netitemshop) | 89 | 18 | （命令族） |
| IB/商城(netgoodsserver) | 23 | 3 | （命令族） |

> ⚠ **未定位**：`C2S_NPC_PETADOPT`(114) 与 `C2S_CONJURE`(125) 在 protocol_map 中归属 netpet，但在 484 脚本全集内无任何 `PacketPrepare` 式发送函数——
> 推测经 NPC 对话/通用派发路径发出，或位于本归档之外；其字段结构待补。netchild 在字典中无 C2S opcode（仅 S2C），已排除。

## 2. 方法学限制（同战斗拆解）
- 栈模拟为**线性扫描**，分支内 `PacketAddI/AddS` 仅采一条路径；
- 字段**值描述**取自函数参数名/字面量，复杂内联表达式保留符号形式；
- `S:N:len` 为变长串；`C2SArrange` 的 `I:param:data` 为长度前缀缓冲字段；
- 语义（★）为基于字段结构与命名的推断，非运行时实证；
- 仅覆盖**客户端发送**结构；对应 S2C 入站字段需另寻接收/解包函数。

*复现：`python dissect_itempet.py`（生成 itempet_opcodes_fields.json）→ `python gen_itempet_report.py`（生成本文件）*
