## 四、引擎实现

### 4.1 状态机

```python
tasks[101] = {'state': 1, 'progress': 0, 'step': 3, 'qid': 101}
```

- `step` = 当前第几步（0 起），`normalize_tasks()` 的「保留未知字段」让它天然可存档；
- `_quest_active()` 只认 `qid in QUESTS` 且 `state == DOING`，不会误伤新手任务 1；
- 单角色同时只跑一条主线：点其他任务的 NPC 会提示「先去 X 找 Y」。

### 4.2 交互与帧

| 客户端动作 | 服务端 | 回帧 |
|---|---|---|
| 点 NPC（op96） | `_npc_quest_dialog()`：接取 / 当前步骤 / 目标提示 / 已完成 | `S2CNpcChatExt(152)`（Q 行 = 选项） |
| 选项 1（op98） | `_quest_answer()` → accept / talk / item / fight / finish | 见下 |
| 接取 | `_quest_accept()` | `S2CTaskAdd(72)` + 对话 |
| 对话推进 | `_quest_advance()` | 同 tid 重发 `TaskAdd`（客户端先 Remove 再建，目标刷新） |
| 交物品 | 跨格计数 → 逐格 `ItemQuantity(35)` / `ItemDel(34)` | 扣完再推进 |
| 剧情战斗 | `_quest_battle` → `_start_war()` | `WarStart` + `WarAdd`（怪名=剧情称谓，造型=SIM） |
| 胜利 | `_after_hero_action()` → `_quest_battle_won()` | 发该步奖励 + `TaskAdd`，然后才走常规经验/掉落 |
| 完成 | `_quest_complete()` | 奖励 + `TaskRemove(73)` + 对话；写入 `quests_done` |

战败/逃跑成功都会清 `_quest_battle`，任务停在本步可重打。

### 4.3 任务栏恢复

`C2S_GET_TASK(48)` 原来只重发新手任务；现在遍历 `tasks` 全量重发（主线也回来）。
这是「重登后任务栏消失」的同源坑，已一并修掉。

### 4.4 剧情点

`m_StoryPoint` = `ITEM_ALL[42]`（TWORD）。登录时随养成同步下发（>0 才发），
获得时即时 `S2CPropChange(42, v, 2)`。上限未做（资料上限未见）。

### 4.5 GM

- 控制台新指令 `grade <n>`（等价 `gm_set_grade`）：主线门槛 10/20/30，试玩不必刷级；
- `gm_state_dict()` 增加 `grade` / `story_point` / `quests.active` / `quests.done`。

## 七、已知边界

1. **「组队战斗」按 1 只敌方模拟**：单机无真实队伍，组队面板的陪同队友不参战；
2. **国籍门槛不校验**：资料第 3 条要求「国籍：加洛」，本服无国籍系统，只校验等级；
3. **剧情 2/3 只做分支级验证**：状态机与 1 完全同源，未逐格跑完 20 步（时间成本），
   步骤数据已全量入库，接 NPC 即可走；
4. **台词是改写**，不是原文；战斗怪物造型是语义近似，均在数据里显式标注；
5. 剧情点目前只累加展示，**没有剧情技能消费端**（点化/附魔/幻化等未实现）；
6. 原版「部分 NPC 接任务后才可见」，本服 quest-spawn NPC **常驻可见**（未做按任务态过滤）——
   好处是玩家能先看到目标，坏处是完成后仍站原地，点它只会得到通用问候。
