# 《梦想世界》战斗 C2S 协议 —— 字段级拆解

> 方法：静态反汇编 `netwar.py`（marshal 代码对象）→ 栈模拟提取每个
> `net.g_Net.PacketPrepare / PacketAddI / PacketAddS` 调用序列 → 还原「opcode + 类型化字段」线序布局。
> 引擎自定义调用约定（方法名两侧压入 net/g_Net 接收者）已特殊处理。
> 字段结构（字节数/顺序）为反汇编实证；字段语义为基于结构与命名的推断（标注★）。
>
> **2026-10-22 复核修正（召唤兽族 + Look 专项，逐条对照 `.pyc` 字节码与调用点）**
> 1. 帧头 **opcode 是 1 字节**（旧文写「opcode 2 字节」，并引用了有缺陷的 `entry_protocol_sim.py` 作证）；
>    C2S 帧 = `[op 1B][N 1B][body N]`，N 不含 opcode。
> 2. **166 的 `id` 是条件字段**：`if op == 0` 才写 `id(4)`；召回（op=1）body 只有 1 字节。
> 3. **169 的 `id` 不上线**：`C2SWarSummPerform(id,target,perform)` 只写 `target(1)+perform(2)`。
> 4. **176 两个函数都是 1 字节单位 id**：`C2SLookWarrior` 的形参名 `order` 名不副实
>    （唯一调用点传 `self.m_ID`）；`C2SWarLook` 在本构建内**无调用点**。
> 5. **175/176 不消耗行动权**、无应答帧（服务端须静默忽略）。
> 详见 `规格/M4_协议规格.md` §3.4。

## 0. 总览

- 战斗 C2S opcode 区间连续：**160 – 177**（18 个整数 opcode）
- 拆解得到 **19 个发送函数**（opcode 176 由两个函数共用：`C2SWarLook` 与 `C2SLookWarrior`）
- 字段类型：`I` = 小端整数（N 字节，native 层 `PacketAddI(v, N)`）；`S` = 字符串（`PacketAddS(s, len)`，定长或变长）
- 线上字节序：`opcode(1B)` + `字段` 依次排列。**C2S 帧头 = `[op 1B][N 1B][body N]`，N 不含 opcode**
  （真机日志 + `tap.py` 分帧 `desync=0` 实证；旧文「opcode 2 字节」及引用 `entry_protocol_sim.py`
  作证的说法已于 2026-10-22 更正——该模拟器是自定包装，不是抓包）

## 1. 逐 opcode 字段详述

### opcode 160 —— 攻击  ★对目标(id)发起普通攻击

- 常量：`C2S_WAR_ATTACK`
- 发送函数：`C2SWarAttack()`
  - 字段（线序）：
    1. `I` 1 整数 = param:id

### opcode 161 —— 使用招式/技能  ★对目标(id)使用招式 perform(2字节技能id)

- 常量：`C2S_WAR_PERFORM`
- 发送函数：`C2SWarPerform()`
  - 字段（线序）：
    1. `I` 1 整数 = param:id
    2. `I` 2 整数 = param:perform

### opcode 162 —— 使用特技  ★对目标(id)使用特技 sid(2字节特技id)

- 常量：`C2S_WAR_SPECIAL`
- 发送函数：`C2SWarSpecial()`
  - 字段（线序）：
    1. `I` 1 整数 = param:id
    2. `I` 2 整数 = param:sid

### opcode 163 —— 防御  ★进入防御姿态，无附加参数

- 常量：`C2S_WAR_DEFEND`
- 发送函数：`C2SWarDefend()`
  - 字段：无（仅 `PacketPrepare` + `PacketSend`，空负载）

### opcode 164 —— 逃跑  ★脱离战斗，无附加参数

- 常量：`C2S_WAR_ESCAPE`
- 发送函数：`C2SWarEscape()`
  - 字段：无（仅 `PacketPrepare` + `PacketSend`，空负载）

### opcode 165 —— 战斗中使用物品  ★对目标(id)使用物品 item(4字节物品id)

- 常量：`C2S_WAR_ITEM`
- 发送函数：`C2SWarItem()`
  - 字段（线序）：
    1. `I` 1 整数 = param:id
    2. `I` 4 整数 = param:item

### opcode 166 —— 召唤/召兽  ★op(1) + **仅 op==0** 时 id(4)

- 常量：`C2S_WAR_SUMMON`
- 发送函数：`C2SWarSummon(op, id)`
  - 字段（线序）：
    1. `I` 1 整数 = param:op（0 = **放出**，1 = **召回**）
    2. `I` 4 整数 = param:id（4 字节召唤体 id，**只有 op==0 才写**）
- 字节码依据：`if op == 0: PacketAddI(id, 4)`（线性栈模拟只见过 5 字节路径，故本表此前漏了条件性）
- 调用点：`warui.CSummonDialog.OnMessage(2)` —— 弹出按钮文案在「召唤」/「召回」之间切换
  （`warui.py:79-85`，判据是「该宠物正在场上」），分别走 `DoAct('summon',True,0,pid)` 与
  `DoAct('summon',True,1,0)`
- 线上：放出 `a6 05 00 e9 03 00 00` / 召回 `a6 01 01`（帧头 `[op][N][body]`）

### opcode 167 —— 保护  ★保护目标(id)

- 常量：`C2S_WAR_PROTECT`
- 发送函数：`C2SWarProtect()`
  - 字段（线序）：
    1. `I` 1 整数 = param:id

### opcode 168 —— 召唤兽攻击  ★召唤兽(id) 攻击 target

- 常量：`C2S_WAR_SUMM_ATTACK`
- 发送函数：`C2SWarSummAttack()`
  - 字段（线序）：
    1. `I` 1 整数 = param:id
    2. `I` 1 整数 = param:target

### opcode 169 —— 召唤兽使用招式  ★对 target 使用招式 perform(2字节)，**无召唤兽 id**

- 常量：`C2S_WAR_SUMM_PERFORM`
- 发送函数：`C2SWarSummPerform(id, target, perform)`
  - 字段（线序）：
    1. `I` 1 整数 = param:target（敌方单位 id）
    2. `I` 2 整数 = param:perform（技能 id）
  - ⚠ **`id` 形参接收但不上线**（字节码里 `LOAD_FAST id` 一次都没出现）；施法者由服务端按
    `war.g_SummonObj` 自己认。按「id+target+perform」解会整体错位。
- 调用点：`warui.DoAct('magic', False, 敌id, 技能id)`（`warui.py:1054`）
- 线上：target=2 pid=415 → `a9 03 02 9f 01`

### opcode 170 —— 召唤兽防御  ★召唤兽(id) 进入防御

- 常量：`C2S_WAR_SUMM_GUARD`

### opcode 172 —— 召唤兽保护  ★召唤兽(id) 保护 target

- 常量：`C2S_WAR_SUMM_PROTECT`
- 发送函数：`C2SWarSummProtect()`

### opcode 173 —— 捕捉宠物  ★对目标(id) 使用捕捉

- 常量：`C2S_WAR_CATCH`
- 发送函数：`C2SWarCatch()`
  - 字段（线序）：
    1. `I` 1 整数 = param:id

### opcode 174 —— 召唤兽逃跑  ★召唤兽(id) 脱离

- 常量：`C2S_WAR_SUMM_ESCAPE`
- 发送函数：`C2SWarSummEscape()`
  - 字段（线序）：
    1. `I` 1 整数 = param:id

### opcode 175 —— 战斗喊话/签名  ★变长字符串 msg（`PacketAddS(msg, len(msg))`，GBK 原样，无长度前缀）

- 常量：`C2S_WAR_TEAM`（★常量名与功能不符：实际是喊话/签名，不涉组队）
- 发送函数：`C2SSendSign(msg)`
  - 字段（线序）：
    1. `S` len(msg) 字符串 = param:msg（长度 = body 剩余字节数；旧表把该字段记成 0 字节是错的）
- 调用点：**Ctrl+右键**战斗单位（`core/warrior.py:1551`），msg = `'#%d@%d' % (heroID, targetID)`
- 线上：`'#1@2'` → `af 04 23 31 40 32`
- ★ 不消耗行动权、服务端无应答（不要回 WarTurn，否则会凭空结束玩家指令窗口）

### opcode 176 —— 查看战斗单位  ★两个发送函数，线上都是 1 字节**单位 id**

- 常量：`C2S_WAR_LOOK`
- ⚠ 本 opcode 由 2 个函数发送：`C2SLookWarrior`（活跃）、`C2SWarLook`（本构建内无调用点）
- 发送函数：`C2SLookWarrior(order)`
  - 字段（线序）：
    1. `I` 1 整数 = **单位 id**（形参名叫 `order`，但唯一调用点传 `self.m_ID`，见 `core/warrior.py:1553`）
- 发送函数：`C2SWarLook(id)`
  - 字段（线序）：
    1. `I` 1 整数 = param:id
- 客户端侧：发完只 `print 'look warrior'`，本地不建命令、无等待态；`NET_FUNCTION_NAME` 里
  **没有**对应 S2C 路由 ⇒ 服务端静默忽略即可，**不消耗行动权**

### opcode 177 —— 召唤子女参战  ★召唤孩子/子女加入战斗，无附加参数

- 常量：`C2S_WAR_SUMMONCHILD`
- 发送函数：`C2SChild()`
  - 字段：无（仅 `PacketPrepare` + `PacketSend`，空负载）

## 2. 关键观察与限制

1. **区间连续性**：160–177 连续无空洞，说明战斗指令是一次性追加编码的协议块。
2. **参数规模分级**：目标 id 多用 1 字节（u8）；技能/特技 id 用 2 字节（u16）；物品/召唤体 id 用 4 字节（u32）——与数值量级匹配（物品/召唤体总数 > 255）。
3. **召唤兽指令族**（166/168–172/174）的 `id` 字段恒等于 `war.g_SummonObj`（由 S2CWarSummon 129 设置）；
   **169 是唯一不带 id 的例外**（施法者由服务端按 `g_SummonObj` 自己认），按「全族都带 id」写解析器必错位。
4. **opcode 176 双发函数**：`C2SWarLook(id)` 与 `C2SLookWarrior(order)` 共用 176，**两者线上都是
   1 字节单位 id**；`order` 只是形参名，唯一调用点传的是 `self.m_ID`。`C2SWarLook` 在本构建内无调用点
   （活跃入口是 Shift+右键 → `C2SLookWarrior`）。
5. **opcode 175 命名错位**：常量名 `C2S_WAR_TEAM` 但发送函数名 `C2SSendSign`，且字段为变长字符串 `msg`——即「战斗签名/口号」功能，归属战斗_team 子系统。
6. **空负载指令**（163 防御 / 164 逃跑 / 177 召唤子女）：仅需 opcode 即可表达动作，无附加参数。

### 方法学限制（重要）
- 栈模拟为**线性扫描**：若 `PacketAddI/AddS` 分布于 `if/else` 分支，仅采集到执行路径上的字段（可能漏掉分支专属字段）。
  **已知实例**：166 的 `if op == 0` 分支被漏采成「固定 5 字节」，2026-10-22 已人工补齐（op=1 时 body 仅 1 字节）。
- 线性扫描**看不到「形参声明了但没写」**的字段：169 的 `id` 就是这一类（不是漏采，是客户端真的不发）。
  判别方法：看字节码里该 `LOAD_FAST` 是否出现，光看函数签名会误判。
- 字段**值描述**取自函数参数名（如 `param:id`）或字面量；内联表达式已尽量化简，复杂运算只能保留符号形式。
  ⚠ 参数名不可当语义：176 的 `order` 实际传的是单位 id。
- `S` 字段若长度参数为变量（如 175 的 `len(msg)`），则线上为变长串，长度 = 实际字符串字节数（GBK），无长度前缀。
- 帧头：C2S 为 `[op 1B][N 1B][body N]`，N 不含 opcode（见 M4 规格 §0.2）；本报告的「字段字节」仅统计 body。
- 以上为**客户端发送结构**；服务端对应 `S2CWar*`（tag=18）的入站字段需另寻接收/解包函数，本报告未覆盖。
