## 2. ★ 主证据：op101 → op151（新分支全链路通过）

```

03:16:46.068  S2C op=151  S2CNpcDetails        pos=5   desc='成长锦囊：售价 1200 金钱。'
```

- 字段由调试台 `OVERLAY[151]`（`pos:1 desc:s`）逐字段解出，与服务端 `build_npc_details`

- **客户端接受了该帧**：悬停后用户直接购买了悬停的那件商品——
  `03:16:47.568 C2S op=99 NPC_BUY index=4 amount=1 → '购买成功：变身宝珠 ×1，花费 1500 金钱，剩余 46449。'`

## 5. op100 验证（活会话帧注入，走真实内核 recv 循环）

`C2SNpcTask(100)` 的客户端触发路径是任务对话框交互（`npc.py:287` 的 m_TaskID/m_Sequence），
UI 较深；本次通过调试台 `/api/inject` 在**真实客户端在线的活会话**上注入 op100 帧
（注入帧经 `TappedConn` 注入队列被内核当正常客户端帧读走，帧流中 `injected=True` 可区分）：

```
# 正路径：任务已接（tid=1）
03:23:07.980  C2S op=100  C2S_NPC_TASK  injected=True   taskid=1 | respond=1
03:23:07.981  S2C op=72   S2CTaskAdd                    tid=1 | name='新手任务' | desc='击败毛草团（0/3）'

# 负路径：任务未接（tid=99）→ 服务端沉默（其后只有客户端自发 op54 移动/op78 生产帧）
03:23:27.965  C2S op=100  C2S_NPC_TASK  injected=True   taskid=99
              （无任何 S2C 应答）
```

- 正路径证明：已接任务的 op100 → 重发 `S2CTaskAdd(72)`（客户端同 tid 先 RemoveTask 再重建，
  进度刷新）——与 `_npc_task_choice` 接任务时下发的帧完全一致。
- 负路径证明：未接任务不造数据、不应答——不会让客户端弹出无中生有的任务。
- 服务端行为与 `tests/_test_dispatch.py` 的进程内断言逐条对应，在真机活会话上复核成立。

## 6. 实验结论

1. **op101/op151 新分支真机验证通过（客户端自发）**：商店悬停 → 服务端按 `SHOP_ITEMS` 生成详情 →
   客户端接收并用于购买决策（悬停后当场买下该商品），全链路无协议错误。
2. **op100 新分支真机验证通过（活会话注入，正/负双路径）**：已接任务重发 TaskAdd、未接任务沉默。
3. 覆盖表 `OVERLAY[151]` 与真机字节一致：调试台逐字段解出的 `pos/desc` 与 `build_npc_details`
   发射值逐位相同——三角一致性（客户端 Unpack / OVERLAY 解码 / build_* 发射）在真机上闭环。
4. `_dispatch` 契约顺序在真机长会话（650+ 帧、跨 5 张图、NPC/商店/传送/任务/移动混合）下稳定；
   本会话 `--no-encounter` 无战斗，战斗态保底路径由 `tests/_test_dispatch.py` 的 32 条契约覆盖。
5. 顺带确认：传送链（5 图互转）、op147 商店列表、op48 宠物信息、op55 方向同步（静默忽略）
   在真机上均正常。
6. 截图证据：`_exp_shot_now.png`（游戏窗口实况：谷雨镇场景 + 底部功能栏 + 「当前登录服务器为本地测试服」）。
