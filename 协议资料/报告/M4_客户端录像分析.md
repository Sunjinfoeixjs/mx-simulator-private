## 2. 客户端状态机（源码证据）

「请等待」= `warui.ShowWait()` 创建的 `wait.igs` 动画（`src/warui.py:2341`）。
它的**显示**与**清除**都是确定路径：

| 动作 | 触发 | 源码 |
|---|---|---|
| **显示**「请等待」 | 客户端发出战斗指令后立即显示 | `warui.py` `SummonAttack`/`SummonItem`/`SummonMagic`/`SummonProtect`（1165/1172/1178/1186）→ `ShowWait()` |
| **清除**（进入下一回合） | 收到 `WarTurn` → `ShowHeroMenu()` → `ShowTimer()` 内 `g_Wait = None` | `warui.py:2244`、`warui.py:2317-2322` |
| **清除**（战斗结束） | 收到 `WarEnd` → `war.WarEnd` → `warui.Hide()` 内 `g_Wait = None` | `src/core/war.py:863`、`warui.py:2354` |

推论：**只要服务端对某条指令不回帧，客户端就会永久停在「请等待」** —— 这正是录像 18.5s 之后的现象。

### 2.1 招式（C2SWarPerform）的帧契约

- 客户端发指令：`warui.DoAct('magic', …)` → `netwar.C2SWarPerform(id, perform)`（`src/netwar.py:8`）
  → 帧体 `id(1) + perform(2)` = **3 字节**，opcode 161。
- 客户端**本地不创建**招式命令；`war.Perform` 命令**只由 `S2CWarPerform`（opcode 122）创建**
  （`src/netwar.py:305` → `war.CCmd(war.Perform)`；处理体 `src/core/war.py:725`）。
- 因此服务端收到 161 后**必须回 122**。回 `AttackNormal`(117) 族只能让普攻命令闭环，
  招式命令始终缺失 → 回合推进异常、下次指令卡死。

### 2.2 战斗结束后的场景契约

`war.WarEnd` 处理（`src/core/war.py:840-868`）会执行：

```
main.SetMainLoop() / mainmenu.SwitchEnv(IsWar=False)
world.ClearAllObject()      # ← 清空地图上所有对象
warui.Hide() / warui.HideWarUI()
```

`ClearAllObject()` 之后客户端**不会**自行重新请求场景 —— 服务端必须重发场景数据，
否则地图为空、战斗单位/等待动画残留（录像 23.7s 之后「切回场景但请等待仍在」即此类）。

### 2.3 `g_WarTimes` 计数陷阱

`S2CWarStart` 让 `g_WarTimes += 1`（`src/netwar.py:165`），`S2CWarEnd` 里：

```
if g_WarTimes == 0:
    return        # ← 计数为 0 时直接丢弃 WarEnd
g_WarTimes -= 1
```

即：**重复下发 `WarStart` 会让计数累积，后续 `WarEnd` 被静默丢弃，战斗永远结束不了。**
