# mxmain.dll 0x43CC50 加密算法还原报告

> 完成日期：2026-10-19
> 方法：静态反编译 + unicorn 沙箱执行原版 `mxmain.dll` 逐字节比对
> 结论：**0x43CC50 已完整还原**，纯 Python 实现见 `sim/mx_crypto.py`

---

## 0. 一句话结论

`0x43CC50` 不是 VMProtect 虚拟化的黑盒，而是**基于 4096 字节密钥表的异或流**。
它的生成器 `0x43CA70` 就躺在 `.text` 里、**完全没有被虚拟化**，
所以「VM 保护、静态不可读」的旧判断只对入口 thunk 成立，对算法本体不成立。

```
密文 = 明文 XOR 密钥表[cursor++ mod 4096]        收发各一份独立状态
密钥表 = gen_43CA70(start)                     1024 字 × 每字 32 步位混合
start  = seed 经 VM 最后一层混淆                 已实测采集（SEED_START 表）
```

## 1. 调用链（逐个确认）

| 地址 | 作用 | 虚拟化？ |
|---|---|---|
| `0x430A60` SetSeed | 入口 | 否 |
| `0x430790` | seed → (A,B,C,D) 四路模扩展 | 否 |
| `0x430AE0` | 发送：复制→`0x43CC50`→socket | 否 |
| `0x430B50` | 接收：socket→`0x43CC50` | 否 |
| `0x43CAF0` | 清状态 + 游标置 4096 | thunk → VM |
| **`0x43CC50`** | **异或流变换** | thunk → VM 入口 |
| **`0x43CA70`** | **密钥表生成器（1024 字）** | **否！** |

`0x43CC50` → `0x9a26c8` 跳进 VM 区段；但 VM 最终把控制权交回
`.text` 里的 `0x43CA70`，而 `0x43CA70` 才是真正干活的地方。

**CNet 对象布局**

| 偏移 | 含义 |
|---|---|
| `+0x72` | 加密开关 |
| `+0x80` | RX 流状态（含 `+0x88` 起 4096 字节表） |
| `+0x1090` | TX 流状态（含 `+0x1098` 起 4096 字节表） |
| `+0x1088/+0x108c` | 发送 A / B |
| `+0x2098/+0x209c` | 接收 C / D |

SetSeed 顺序：
```
(A,B,C,D) = 0x430790(seed)
0x43CAF0(RX, A); 0x43CC50(RX, NULL, B)     ← B 是 RX 预热量
0x43CAF0(TX, C); 0x43CC50(TX, NULL, D)     ← D 是 TX 预热量
[this+0x72] = 1
```

## 2. 密钥表生成器 `0x43CA70`（核心）

```asm
0x43CA7D  eax = ctx[0]              ; start
0x43CA7F  ecx = 0x400               ; 1024 个字
0x43CA84  esi = 0xDA3A2A9C          ; 掩码常数
loop:                               ; 外层 1024 次
  ecx = 0x20                        ; 内层 32 步
  step:
    ebx = eax
    eax = eax << 1
    ebx = ebx & 0xDA3A2A9C
    edx = ebx
    ebx = bswap(ebx)
    bx  = bx ^ dx
    bh  = bh ^ bl                   ; 由该结果决定 PF
    jp  skip_inc                    ; PF==1(偶) → 跳过
    eax = eax + 1                   ; 奇校验 → 加一
  [edi] = eax ; edi += 4            ; 写出一个字，eax 继续链式推进
```

关键：**每个字 = 从上一个字继续走 32 步的结果**，不是独立生成。

验证：15 个种子 × 2 方向 × 1024 字 == 原版 DLL 内存中的表，**100% 逐字节一致**。

## 3. 异或流 `0x43CC50`

```
if cursor == 4096:            # 首次或耗尽 → 重新填表
    table = gen_43CA70(start)
    cursor = 0
for i in range(len):
    buf[i] ^= table[cursor]
    cursor = (cursor + 1) & 0xFFF
```

- 纯 XOR 流，`ct = pt ^ ks`
- 同方向**跨包连续推进**（TCP 有序，客户端就是这么用的）
- 空调用不推进

---

## 4. 唯一未闭合的一环：seed → start

`start` 由 seed 经 VM 最后一层混淆产生，实测性质：

- **忽略最高位**：`start(seed) == start(seed | 0x80000000)`
- **非线性**（非 GF(2) 线性），是带密钥混淆
- 与 `0x430790` 的 A/B/C/D 无简单代数关系

因此以**实测真值表**形式收录（`mx_crypto.SEED_START`，15 个种子）。
服务端自选 seed，故可只使用表内种子；需要新种子时用
`sim/re_crypto/collect_seeds.py` 采集后补表即可。

---

## 5. 实测边界（重要且诚实）

多次重跑同一 (seed, 方向) 的结果：

| 区间 | 行为 |
|---|---|
| `[0, 448)` | **完全确定**，与还原模型逐字节一致 |
| `>= 448` | **DLL 自身多次重跑就互相不一致**（后续走未初始化/非确定路径）|

个别种子某方向更短：`0x03` 的 RX 只有 46 字节，`0x100` 的 RX 只有 116 字节
（已逐条实测记录在 `_USABLE`）。

**实战影响：无。** 客户端真实报文远小于 448 字节（登录包 < 200）。

```python
from mx_crypto import RealCipher

c.crypt_tx(plaintext)   # 发送方向
c.crypt_rx(ciphertext)  # 接收方向
```

（唯一不一致在 448 边界处的非确定区，符合第 5 节结论）。

## 7. 对旧结论的更正

| 旧判断 | 实际 |
|---|---|
| `0x43cc50` 在 VMProtect 区段、静态不可得 | 入口 thunk 在 VM 区，**算法本体 `0x43CA70` 在 .text、未虚拟化** |
| 需要动态断点抓三元组拟合 LCG | 不需要；静态即可完整还原，动态仅用于最终逐字节验证 |
| 是 LCG/PRNG 常数待定 | 不是 LCG，是 32 步位混合链式生成器 + 异或表 |
